# Документация проекта «Aitest»

Это рабочая документация проекта. Перед началом каждой сессии необходимо считывать
содержимое папки `docs`, чтобы погрузиться в контекст. Новые знания, ограничения
и принятые решения фиксируются здесь по итогам каждой сессии.

## Оглавление

- [Вводная информация по проекту](project-overview.md)
- [Требования и особенности формата EDT](edt-requirements.md)

## Вводная информация (кратко)

- **Проект**: разработка конфигурации 1С с нуля в рамках учебного курса.
- **Цель**: создать приложение, умеющее работать с Kimi API, и на примере этой работы
  продемонстрировать различные возможности современных LLM.
- **Порядок работы**: ежедневные задания, идущие по нарастающей; каждое следующее задание
  основывается на результатах предыдущих циклов.
- **Роли**:
  - Заказчик/приемщик: ставит задачи, корректирует предлагаемые решения, проводит
    итоговую приемку.
  - Разработчик: ИИ-агент (Kimi Code), действующий как полноценный разработчик 1С.
    Выполняет доработки по стандартам разработки 1С и ведет документацию в `docs`.

## Технический контекст

- Проект в формате 1C:EDT (папка `src/Configuration`, файл `Configuration.mdo`).
- Имя конфигурации: `aitest`, синоним «Aitest».
- Режим совместимости: **8.3.27**.
- Вариант встроенного языка: **русский**.
- Режим запуска: управляемое приложение (тонкий клиент), назначение — персональный компьютер.
- Язык конфигурации: русский (по умолчанию).

## Зафиксированные ограничения

- Запрещено использование модальных окон (`modalityUseMode = DontUse`) — только
  асинхронные методы и неблокирующие диалоги.
- Запрещены синхронные вызовы расширений платформы и внешних компонент
  (`synchronousPlatformExtensionAndAddInCallUseMode = DontUse`) — HTTP-запросы и прочие
  внешние вызовы выполняются только асинхронно.
- Разработка ведется в локальном git-репозитории:
  - рабочая ветка — `dev`, все изменения коммитятся туда;
  - в ветку `main` изменения вливаются только после приемки заказчиком по его запросу.
